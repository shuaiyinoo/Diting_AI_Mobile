# Diting AI Mobile v1.0.2 更新

> 修复版本。v1.0.0 首次打包因**类型检查未通过**与 **CI 环境差异**未能发布成功，本版本完成全部修复，是**首个成功产出 Android / iOS 双端安装包**的版本。

---

## 🐛 Bug 修复

### 构建与类型检查（17 处）

修复 `vue-tsc` 全部类型错误，`npm run build`（生产构建 + 类型检查）完整通过：

- **SelectItem 组件** — `value` 类型对齐 reka-ui 的 `AcceptableValue`（boolean 不在合法取值内）。
- **WidgetNode** — 移除未使用的 `watch` 导入。
- **useRemoteSession** — 编解码器类型改为从 `RTCRtpSender.getCapabilities` 返回值提取元素类型，不硬编码全局接口名（兼容各版本 lib.dom）；`start()` 保留兼容签名并注明 token 已由全局信令连接持有。
- **signaling** — 移除死存储的 `private token` 字段（连接头直接使用参数，stompjs 重连自动复用）。
- **MessageBlock 类型补齐 `text` 变体** — 与流式同步协议实际数据对齐，`text_start` 事件块的类型比较恢复正常，移除 `as any`。
- **ChatView / AgentView** — `defineEmits` 事件名对齐模板中的 kebab-case 触发（`toggle-sidebar`）。
- **会话列表类型** — `ChatSessionItem` / `AgentSessionItem` 补充 `preview` 可选字段（列表副标题）。
- **MessageRenderer** — 同步 `text` 块类型；`getProcessBlocks` 用类型谓词收窄返回值（text 块自然排除在过程块之外）。

所有修复**只动类型、零运行时行为变更**。

### CI/CD 流水线（Android / iOS 双端打通）

- **Android：JDK 17 → JDK 21** — Capacitor 8 的 Android 模块要求 `sourceCompatibility 21`，JDK 17 编译失败（`invalid source release: 21`）。
- **Android：sdkmanager 路径修复** — GitHub runner 的 `sdkmanager` 不在默认 PATH，改为从 `$ANDROID_HOME/cmdline-tools` 定位完整路径；platform 36 已预装时自动跳过安装。
- **依赖安装策略** — `npm ci` 改为 `npm install`：不再要求 `package-lock.json` 与 `package.json` 严格同步，lock 过期不再阻塞构建。
- **iOS：未签名构建产物路径修复** — `CODE_SIGNING_ALLOWED=NO` 时 `xcodebuild archive` 不会把 `App.app` 放进 `.xcarchive/Products/Applications`（留在 DerivedData 归档中间目录），导致打包 IPA 找不到产物；改用普通 `xcodebuild build` + 显式 `-derivedDataPath`，产物路径固定为 `Build/Products/Release-iphoneos/App.app`。
- **iOS：产物自检** — 未找到 `App.app` 时自动搜索并列出实际产物路径，便于排查。
